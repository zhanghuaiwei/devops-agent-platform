# 06 测试与质量(pytest + ruff)

> 前置:完成 03~05 任意一节后即可穿插进行。

## 一、测试金字塔(本项目的取舍)

```text
        ┌──────────┐
        │ Agent 集成 │  少:真实 LLM 调用,贵且慢,手动跑
        ├──────────┤
        │ 端点测试   │  中:TestClient + mock LLM/Tool
        ├──────────┤
        │ Tool 单测  │  多:纯函数/外部依赖 mock,CI 必跑
        └──────────┘
```

**核心认知:LLM 是不确定的,所以测试必须把它隔离掉。** 测的是"你的代码逻辑",不是"模型智商"。

## 二、mock LLM 的两种方式

```python
# 方式 1:LangChain 的 FakeListLLM(按顺序返回预设文本)
from langchain_core.language_models.fake import FakeListLLM
llm = FakeListLLM(responses=[
    'Thought: 需要查日志\nAction: docker_logs\nAction Input: {"service_name":"web"}',
    'Final Answer: 容器运行正常',
])

# 方式 2:mock Tool 层,保留真实 LLM 集成(手动跑,不进 CI)
```

方式 1 进 CI:断言"输入 X → Agent 调了 Y 工具 → 端点返回 Z 结构"。

## 四、ruff 质量门(已在 pyproject.toml 配好)

- `ruff check .`:含 bandit 安全规则(S)、异步反模式(ASYNC)—— CI 的 agent-engine job 执行
- `ruff format .`:格式化,与 pre-commit 共用配置,不产生"格式之争"
- 覆盖率门槛:`agents/`、`tools/` ≥ 70%(pyproject 已配 `--cov=app`)
