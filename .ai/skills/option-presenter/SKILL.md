# Option Presenter Skill(列方案 + 举一反三)

## 何时触发

- 用户的问题涉及"怎么做 / 选什么 / 哪种方案 / 如何实现 / 要不要做"等**存在多种解法**的场景
- **例外,直接作答不列方案**:事实性问答(如"superpowers 是什么")、明确的单步指令、用户已说"直接做/别问了"

## 第一步:列方案(供用户选择)

给出 2~4 个候选方案,每个方案包含四项,保持紧凑:

- **核心思路**(一句话)
- **优点**(1~2 条)
- **代价**(1~2 条:成本、风险、维护负担)
- **适用场景**(什么情况下选它)

输出要求:
- 方案之间必须有真实差异,禁止"换皮方案"凑数
- 末尾给出**推荐**及推荐理由(结合本仓库约束:版本红线、代码边界、学习者优先)
- 信息不足以列方案时,先问 1~2 个关键问题,不要硬猜

## 第二步:举一反三(结论之后)

用户选定方案或接受推荐后,附"举一反三"小节,从以下维度中挑 1~3 个**真正相关**的展开(没有就略过,不硬凑):

- **同类变体**:同一思路还能解决本项目的哪些相邻问题(举具体文件/模块例子)
- **反向边界**:该方案不适用的场景、常见误用、什么时候要换方案
- **后续连锁**:落地后紧接着要面对的问题——测试怎么补、监控怎么加、回滚怎么做、团队约定怎么同步

## 反例(禁止)

- 只给一个方案直接开干(违反"先问后写",见 `.ai/rules/workflow.md`)
- 列了方案但不给推荐,把选择负担完全丢回用户
- 举一反三变成复读:把结论换种说法再讲一遍
